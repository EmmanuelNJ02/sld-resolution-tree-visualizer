## 1. Purpose

This document defines the JSON file produced by the SLD tree builder (Part B) and consumed by the web visualizer (Part C).

Part C must only **read and display** this file. It must not reproduce SLD resolution or tree construction logic.

## 2. How the File Is Produced

From the repository root, with the example programs loaded:

```prolog
?- export_tree_json(Query, MaxDepth, 'examples/json/name.json').
```

Ready-made example files are generated with:

```cmd
swipl -q -s examples/programs/family.pl -s examples/programs/recursive_loop.pl -s examples/generate_json_examples.pl -g generate_examples -t halt
```

| File | Query | Max depth | Case |
|---|---|---:|---|
| `examples/json/multiple_solutions.json` | `parent(ana, X)` | 3 | Two solutions |
| `examples/json/failure.json` | `parent(diego, X)` | 3 | Root failure, no solutions |
| `examples/json/backtracking.json` | `parent(ana, X), parent(X, diego)` | 3 | Failed branch, backtracking, one solution |
| `examples/json/recursion.json` | `ancestor(ana, X)` | 4 | Recursive rule, four solutions |
| `examples/json/cutoff.json` | `endless` | 3 | Infinite recursion stopped by the depth limit |
| `examples/json/mixed.json` | `loop` | 3 | Recursion with alternatives: cutoff and successes |

## 3. Top-Level Object

```json
{
  "query": "parent(ana,A),parent(A,diego)",
  "maxDepth": 3,
  "nodes": [ ... ],
  "answers": [ ... ]
}
```

| Field | Type | Meaning |
|---|---|---|
| `query` | string | Original query, as text. |
| `maxDepth` | number | Depth limit used for the resolution. |
| `nodes` | array of node objects | All tree nodes, in creation (depth-first) order. The first node is always the root. |
| `answers` | array of answer objects | Successful solutions, in the order they were found. Empty if there are none. |

## 4. Node Object

```json
{"id": "n2", "parent": "n0", "path": [2], "depth": 1,
 "goal": "parent(ana,A)", "clause": "parent(ana,marta)",
 "pending": ["parent(marta,diego)"], "bindings": [{"var": "V1", "value": "marta"}],
 "status": "success", "children": ["n3"]}
```

| Field | Type | Meaning |
|---|---|---|
| `id` | string | Unique node identifier: `n0`, `n1`, `n2`, ... `n0` is the root. |
| `parent` | string or `null` | `id` of the parent node. `null` only for the root. |
| `path` | array of numbers | Clause-choice positions from the root. Root: `[]`. `[2, 1]` = second alternative at the root, then first alternative. |
| `depth` | number | Number of clause applications from the root. Root: `0`. |
| `goal` | string | **Root:** the full query. **Other nodes:** the goal that was resolved in the parent to reach this node. |
| `clause` | string or `null` | Fact or rule applied to reach this node (the edge label). `null` for the root. |
| `pending` | array of strings | Goals that remain to be solved at this node. Empty array = nothing left (success). |
| `bindings` | array of binding objects | Values of the original query variables at this node. |
| `status` | string | Outcome of the branch below this node. See section 6. |
| `children` | array of strings | `id`s of the child nodes, in clause order. Empty array = leaf. |

### Edge information

There is no separate edge list. Each non-root node describes the edge that arrives at it:

```text
parent  --[ goal resolved with clause ]-->  node
```

## 5. Binding Object

```json
{"var": "V1", "value": "luis"}
```

| Field | Type | Meaning |
|---|---|---|
| `var` | string | Query variable label: `V1`, `V2`, ... in the order they appear in the query. |
| `value` | string | Current value as Prolog text. `"_"` means the variable is still unbound. |

Variables inside `goal`, `clause` and `pending` texts (`A`, `B`, ...) are display names generated by Part A. They do not necessarily match the `V1`, `V2` labels.

## 6. Status Values

| Status | Leaf node | Inner node |
|---|---|---|
| `success` | All goals were solved. | At least one child branch is `success`. |
| `failure` | No clause matches the selected goal. | All child branches are `failure`. |
| `cutoff` | The depth limit stopped the branch. | No child is `success`, and at least one is `cutoff`. |

`cutoff` does **not** mean the query is false. It means the search was stopped before reaching an answer. Part C should display it differently from `failure`.

With this rule, the path from the root to every solution is marked `success`, which allows the visualizer to highlight it.

## 7. Answer Object

```json
{"node": "n3", "bindings": [{"var": "V1", "value": "marta"}]}
```

| Field | Type | Meaning |
|---|---|---|
| `node` | string | `id` of the successful leaf node where the solution was found. |
| `bindings` | array of binding objects | Values of the query variables for that solution. |

## 8. Complete Example

Query: `parent(ana, X), parent(X, diego)` with `maxDepth = 3` (`examples/json/backtracking.json`).

```json
{
  "query": "parent(ana,A),parent(A,diego)",
  "maxDepth": 3,
  "nodes": [
    {"id": "n0", "parent": null, "path": [], "depth": 0,
     "goal": "parent(ana,A),parent(A,diego)", "clause": null,
     "pending": ["parent(ana,A)", "parent(A,diego)"], "bindings": [{"var": "V1", "value": "_"}],
     "status": "success", "children": ["n1", "n2"]},
    {"id": "n1", "parent": "n0", "path": [1], "depth": 1,
     "goal": "parent(ana,A)", "clause": "parent(ana,luis)",
     "pending": ["parent(luis,diego)"], "bindings": [{"var": "V1", "value": "luis"}],
     "status": "failure", "children": []},
    {"id": "n2", "parent": "n0", "path": [2], "depth": 1,
     "goal": "parent(ana,A)", "clause": "parent(ana,marta)",
     "pending": ["parent(marta,diego)"], "bindings": [{"var": "V1", "value": "marta"}],
     "status": "success", "children": ["n3"]},
    {"id": "n3", "parent": "n2", "path": [2,1], "depth": 2,
     "goal": "parent(marta,diego)", "clause": "parent(marta,diego)",
     "pending": [], "bindings": [{"var": "V1", "value": "marta"}],
     "status": "success", "children": []}
  ],
  "answers": [
    {"node": "n3", "bindings": [{"var": "V1", "value": "marta"}]}
  ]
}
```

Tree represented by this file:

```text
n0  parent(ana,A), parent(A,diego)            success
├── n1  [parent(ana,luis)]   parent(luis,diego)    failure
└── n2  [parent(ana,marta)]  parent(marta,diego)   success
    └── n3  [parent(marta,diego)]  (no goals)      success   <- answer: X = marta
```

## 9. Guarantees for Part C

1. The file is valid JSON (verified in `tests/integration/sld_integration_tests.pl` by reading it back with a JSON parser).
2. There is exactly one root, and it is the first element of `nodes`.
3. Every `parent` and every element of `children` refers to an existing `id`.
4. Every `answers[].node` refers to an existing node whose `status` is `success`.
5. Text values are escaped (`"` and `\`), so they can be inserted safely as text.
6. `null` is used only for the root's `parent` and `clause`.
